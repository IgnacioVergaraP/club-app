SERVICIO Y SEPARACIÓN MULTICLUB
AdminDemoService se provee en el módulo administrativo. Usa BehaviorSubject privado y context$ con el club y dashboard del ID seleccionado. Un ID desconocido se ignora.
Cada emisión crea copias nuevas del club, settings, dashboard y registros de sus colecciones, incluidas ventas recientes. Los productos destacados se ordenan por unidades de ejemplo. La lista del selector también contiene copias. Las pruebas verifican que mutaciones de una instantánea no afecten otra suscripción.
Cada club tiene sus propios productos, eventos, actividad e indicadores. Al cambiar de club se reemplaza el contexto completo; las pantallas provisionales conservan la selección dentro de la SPA. Al recargar vuelve a Órbita.
No hay HttpClient, API, escritura, almacenamiento del navegador ni lectura de pedidos en este servicio. No depende de OrdersService, WalletService, ProfileService o servicios Fintoc.
La separación local prepara el contrato visual; no implementa aislamiento de tenants, permisos ni seguridad de servidor.

AdminPlaceholderComponent se reutiliza para las seis secciones. Observa route.data para actualizar el título al navegar entre rutas que reutilizan el componente. No hay botones de CRUD ni acciones comerciales.

El acceso al administrador es por /admin; no se añadió una sexta pestaña ni un enlace administrativo a la navegación comercial aprobada. El enlace del panel permite regresar a Inicio; también se comprobó el acceso directo nuevamente al administrador.
