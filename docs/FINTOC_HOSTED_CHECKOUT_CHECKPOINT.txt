CLUB VOID — FINTOC CHECKOUT ALOJADO (SANDBOX)
Fecha: 06-11-2026

ALCANCE Y ESTADO
Implementado el botón Pagar con Fintoc · Sandbox en el checkout de bebidas, según la documentación adjunta del Product Owner. Coexiste con Apple Pay Express Checkout; no sustituye ni modifica la Wallet DEMO o Perfil.
Verificados creación real de sesión, redirección a Fintoc y regreso real mediante Volver. No se completó un pago en la página del proveedor; no se declara una prueba real de pago exitoso. Estados de éxito/fallo/requires_action se verificaron con proveedor simulado en tests.
No se activaron producción, webhooks, persistencia, pagos reales, emisión de entradas ni canjes. Este trabajo es un ajuste autorizado directo del checkout, sin asignarle automáticamente una subetapa 3.6.

FUNCIONAMIENTO
1. El usuario selecciona bebidas y prepara el pedido existente en Flask.
2. Si no hay diferencia entre el importe estimado y el de Flask, aparece Pagar con Fintoc · Sandbox.
3. Angular envía únicamente order_id a Flask. No envía importe, moneda ni URLs de retorno.
4. Flask usa el total CLP del pedido, la clave secreta test y el cliente HTTPS existente para crear /v2/checkout_sessions.
5. El navegador se dirige a redirect_url validada y Fintoc muestra sus métodos habilitados.
6. Fintoc devuelve al frontend en /checkout/resultado. Esa ruta funciona sin carrito y consulta el estado en Flask.
7. Flask recupera la sesión desde Fintoc. Solo payment_intent succeeded en sesión finished, con modo, moneda, importe y pedido coincidentes, se presenta como pago Sandbox verificado.
La URL de retorno y parámetros como verified=true nunca bastan para declarar éxito. El pedido comercial conserva su estado de demostración; no se emiten registros Wallet.

REINTENTOS Y COEXISTENCIA CON APPLE PAY
Una sola modalidad por pedido, coordinada por el mismo servicio backend y sus locks. Una vez que se inicia Checkout alojado, se oculta Apple Pay para ese pedido y se bloquea preparar otro pedido desde esa vista. Si Apple Pay ya tiene un intento en curso, el botón alojado se deshabilita. Backend también rechaza la mezcla de modalidades con HTTP 409.
Reintentos de creación conservan payload y clave de idempotencia. Una sesión creada se reutiliza con HTTP 200. La ruta de retorno permite verificar de nuevo y continuar el mismo intento cuando la sesión sigue en created/in_progress. No ofrece reanudar un pago confirmado o pendiente de acción adicional.
No se agregaron dependencias. Se reutiliza http.client del backend y Angular/RxJS existentes.

COMPATIBILIDAD COMPROBADA CON FINTOC
Se conserva Fintoc-Version 2026-02-01 existente.
La API real con esa versión rechazó ui_mode:hosted (HTTP 400). Se corrigió omitiendo ui_mode para Checkout alojado, como en el ejemplo adjunto. La respuesta de esa versión incluye ui_mode:null; también se admite hosted para compatibilidad, y se rechaza embedded en este flujo.
La API Sandbox real devuelve redirect_url en test.pay.fintoc.com. Lista exacta de destinos HTTPS admitidos, tanto en backend como frontend:
- test.pay.fintoc.com (observado en pruebas reales)
- pay.fintoc.com (ejemplo de la guía)
- checkout.fintoc.com (referencia del objeto)
Se rechazan otros dominios, HTTP, credenciales en URL, puertos distintos de 443, fragmentos y espacios.
No se añadieron dominios comodín ni se desactivaron validaciones TLS.
Documentación oficial consultada:
https://docs.fintoc.com/guides/payments/accept-a-payment
https://docs.fintoc.com/api/payments-api/checkout-sessions/checkout-session-object
La respuesta real fija el contrato compatible cuando difiere de ejemplos recientes; la versión no se cambió para ocultar esa diferencia.

CONFIGURACIÓN
backend/.env existente:
- FINTOC_SANDBOX_ENABLED=true
- FINTOC_SECRET_KEY con prefijo sk_test_
- FINTOC_PUBLIC_KEY sigue siendo necesaria para Apple Pay Express, no para el botón alojado.
Nueva variable opcional:
FINTOC_CHECKOUT_BASE_URL=http://localhost:4200
Es el origen público de Angular para success_url/cancel_url. Por defecto usa localhost:4200. En un entorno HTTPS debe configurarse con el origen real sin ruta, query o fragmento, por ejemplo https://app.ejemplo.cl. Solo localhost/127.0.0.1 admiten HTTP.
Se agregó el ejemplo a backend/.env.example. No se modificaron ni expusieron las claves locales.
Reiniciar Flask después de cambiar la configuración. El hosting Angular deberá servir su index para la ruta /checkout/resultado.

PENDIENTES Y LIMITACIONES
- Completar un pago Sandbox exitoso o fallido en el proveedor y verificar su resultado real. Los estados finales se cubrieron con tests simulados; no se declaran como una prueba de pago real completada.
- Dominio HTTPS y habilitación Apple Pay Express continúan como pendientes independientes.
- No hay webhooks, base de datos, reconciliación en segundo plano ni autenticación. Solo se consulta Fintoc al regresar o al pulsar Verificar estado. La guía oficial recomienda eventos posteriores al pago para una integración comercial completa.
- Pedidos/intentos se conservan en memoria de un proceso Flask. Un reinicio pierde la asociación; no apto para uso comercial en producción.
- Carrito y Perfil siguen en memoria del frontend: salir a una página externa/recargar puede restablecerlos. La pantalla de retorno funciona por order_id, sin depender de ese carrito, y permite continuar el mismo intento cuando corresponde.
- Si la sesión/cotización venció, el servidor impide continuar ese pago. Volver a Tragos/carrito para preparar un pedido vigente.
- El nombre del comercio CODETEC se debe revisar en la configuración de Fintoc si se requiere otra presentación; no se modificó información comercial/legal de la cuenta.
- Validación visual del Product Owner y pruebas en dispositivos físicos pendientes.
- Wallet conserva exclusivamente sus registros DEMO independientes de pagos, incluso ante éxito Sandbox verificado.
