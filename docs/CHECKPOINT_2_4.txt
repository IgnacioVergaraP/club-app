Configuración
El usuario configuró FINTOC_SECRET_KEY y FINTOC_PUBLIC_KEY en backend/.env.
Se habilitó FINTOC_SANDBOX_ENABLED=true únicamente en ese archivo local.
No se imprimieron claves ni tokens. .env.example contiene valores vacíos y flag
false; backend/.gitignore excluye .env y sus variantes, salvo el ejemplo.
No se añadieron secretos a Angular ni se modificaron environment.ts/development.ts.
No se instalaron dependencias; backend/requirements.txt permanece igual.

Endpoints internos implementados
GET /api/payments/fintoc/config
- Configuración publicable: enabled, public_key (solo pk_test) y mode=test.
- Configuración inválida/deshabilitada -> enabled=false, public_key=null.
POST /api/payments/fintoc/checkout-session
- Recibe únicamente {order_id}. No acepta amount, currency, estados ni referencias
  de pago proporcionadas por el cliente.
- UUID existente, pedido pending_payment no vencido, importe de su snapshot backend.
- 201 al crear sesión; 200 al recuperar el token de la misma sesión.
- Devuelve únicamente {session_token}; errores JSON consistentes y sin detalles sensibles.
GET /api/payments/fintoc/orders/<order_id>/status
- Consulta la referencia de sesión que Flask tiene asociada, nunca un payment ID
  elegido por el navegador. Devuelve verified, mode, status y order_id.
Los tres endpoints usan Cache-Control: no-store.

API oficial e implementación Python
La documentación del usuario se contrastó con referencias oficiales vigentes.
Existe SDK Python oficial; se eligió HTTPS mediante http.client de la biblioteca
estándar para implementar estas dos operaciones sin agregar una dependencia.
Host fijo api.fintoc.com y TLS por defecto; no se aceptan URLs externas del cliente.
POST /v2/checkout_sessions y GET /v2/checkout_sessions/{id}.
Authorization contiene exclusivamente la clave secreta en el backend.
Se fija Fintoc-Version: 2026-02-01 según la referencia actual.
Creación: flow=payment, ui_mode=embedded, amount=order.total_clp, currency=CLP,
payment_method_types=['card'], metadata.order_id y expires_at del pedido.
No se envían split, business_profile, datos de tarjetas o un destinatario inventado.
Para card no se añadió recipient_account de transferencia bancaria.

Idempotencia y expiración
Un intento/sesión por UUID de pedido, protegido por lock por intento.
Clave remota estable derivada del UUID del pedido y payload almacenado antes de
llamar a Fintoc. Un timeout conserva ambos para el siguiente reintento.
Solicitudes concurrentes no crean varias sesiones; una operación en curso devuelve 409.
Una sesión ya verificada no permite otra creación para ese pedido.
No se rota una clave automáticamente ante errores ambiguos o timeouts.
Fintoc exige expiración al menos 10 minutos en el futuro: la primera sesión se
rechaza si la cotización de 15 minutos tiene menos de 10 minutos y 5 segundos.
Antes de iniciar un intento, Preparar pedido puede renovar esa cotización. Una vez
iniciado un intento se bloquea preparar otro hasta resolverlo o comprobar un fallo.
Las sesiones quedan limitadas por el vencimiento del pedido.

Verificación confiable
GET autenticado de sesión desde Flask; se contrastan id, metadata.order_id,
importe entero, moneda CLP, flow=payment, método card y mode=test.
Se valida payment_resource.payment_intent, su importe, moneda, método y modo.
verified=true solo con sesión finished y payment_intent succeeded coincidente.
Respuesta de navegador/SDK no se acepta como prueba de pago.
No se implementan webhooks en esta fase: se usa la consulta documentada de Fintoc.
La verificación puede recuperar un pago legítimo aun si la cotización ya venció.

Estados de pedido
Se conservan pending_payment, expired y cancelled. El resultado del pago Sandbox
es un estado separado del intento. No se agregó una ruta para marcar pedidos paid.
La UI muestra Pago Sandbox verificado solo tras la respuesta de verificación
coincidente del backend. No se emiten entradas, consumos, QR o autorizaciones reales.
Esta separación es intencional para la prueba sin persistencia ni entrega comercial.

SDK Angular
Nuevo FintocExpressCheckoutComponent, standalone:false, declarado en AppModule.
FintocSdkService carga una única vez https://js.fintoc.com/v1/ directamente en head;
no se descarga, empaqueta ni aloja una copia local. Admite reintento de carga.
Contenedor único por componente, creado antes de Fintoc.create, con monto del pedido.
product=payments, country=cl, currency=CLP, botón Apple Pay buy/white, 52 px,
borde 12 px y locale es-MX, siguiendo las opciones documentadas.
El botón oficial solo es visible tras wallets.applePay=true; no se dibuja un botón falso.
Al destruir/cambiar el componente se cancela el ciclo, se limpia el reloj y se llama
widget.destroy(); callbacks de generaciones anteriores se descartan.
Bloqueo de callbacks duplicados durante obtención de sesión y espera de resultado;
se desactivan interacciones del contenedor durante el procesamiento.
Se monta solo con pedido y sin diferencia entre importe estimado y backend.
Google Pay sigue Próximamente. No se modifica Wallet ni el flujo de entradas.

Callbacks y eventos
onPaymentRequest: solo card/apple_pay; POST a Flask solo order_id; retorna
{sessionToken}. Timeout frontend 15 s, bajo el límite SDK de 30 s; HTTPS backend
con timeout de socket de 10 s. Los errores no incluyen tokens ni mensajes internos.
express_checkout_ready: interpreta metadata.wallets.applePay.
processing_express_checkout_payment: carga y bloqueo de preparación duplicada.
payment_error: mensaje de error, libera carga y permite reintento de la misma operación.
express_checkout_error: informa fallo de inicialización/disponibilidad.
onExit: informa cierre o cancelación; no lo clasifica como rechazo de pago.
onSuccess: ignora datos como prueba, consulta Flask y espera verificación.
Verificar estado Sandbox permite repetir la consulta sin iniciar otro pago.
Preparar otro pedido permanece bloqueado con un intento sin resolver.
El carrito de bebidas se conserva.

Problemas y riesgos técnicos
- Almacenamiento temporal de pedidos/intentos: no resiste reinicios ni coordina
  múltiples workers o réplicas. El reinicio pierde la referencia para consultar
  sesiones ya creadas; no es una solución transaccional para producción.
- API de demostración anónima: un UUID no sustituye autenticación/autorización de
  producción. No se habilitan claves live ni entrega de bienes.
- Algunos errores 5xx pueden quedar guardados por la idempotencia del proveedor;
  no se cambia la clave automáticamente. Pueden requerir conciliación con Fintoc.
- El backend verifica por consulta; no hay persistencia, conciliación automática,
  recuperación tras reinicios ni webhooks de producción.
- Continúan avisos de bundle >500 kB y estilos existentes; sin errores de build.
  Dos selectores Bootstrap .form-floating>~label siguen omitidos por CSS.
- API URL de producción todavía es un marcador: configurar API HTTPS y CORS al
  preparar el dominio de pruebas, según FINTOC_SANDBOX_SETUP.txt.
- No se instalaron dependencias ni se agregaron SDKs de Google Pay, split o pagos live.
